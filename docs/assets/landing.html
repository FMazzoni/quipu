quipu (qp)

A structured, observable task substrate for AI agent orchestration.

Agents need somewhere to put work: what is ready, who claimed it, what it depends on, and why a decision was made. qp is that place — a per-project SQLite database behind a small CLI. One static binary, no daemon, no server, no async runtime.

It is deliberately pattern-agnostic. Waves, critique loops and branch-and-evaluate are workflows an agent skill drives on top of the primitives; they are not baked into the binary.

Install

curl -sSfL https://raw.githubusercontent.com/FMazzoni/quipu/main/install.sh | sh

Or build from source: cargo install --git https://github.com/FMazzoni/quipu.

First minute

qp init
qp add "implement parser" --tag wave:1          # → QP-1, state=ready
qp add "wire CLI" --depends-on QP-1 --tag wave:1  # → QP-2, state=pending
qp claim QP-1 --as alice
qp complete QP-1 --as alice --decision "chose pest"
qp tree
qp decisions

Every mutating command takes --json, so an agent reads results instead of scraping them.

The name. A quipu (also spelled khipu) is the knotted-cord recording device the Inca used to keep accounts and archives — state held in structure rather than in prose. That is the idea here: the knots are the record, and anyone who knows how to read them can pick up the thread.
